The plan does not silently adapt to the draft-form server. Either it refuses that form by default and supports it only through a setting the user sets for that server, or it accepts the form as the one allowed exception: an earlier form of the same extension, mapped onto the spec's behaviour with nothing added, turned off by one setting, and stated in the README as going beyond the spec. A plan that detects the draft form and adapts to it with no such off setting or statement fails.
